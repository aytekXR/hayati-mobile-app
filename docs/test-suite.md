# Test Suite Strategy — Hayati

Strict TDD (rule #6). The pyramid, tooling, and gates below are enforced by CI, not by good intentions.

## 1. Layers

### Unit tests (`test/`, mirrors `lib/`) — the wide base
Pure-Dart domain layer makes these cheap and fast. Mandatory targets: streak engine (property-based: gaps, grace tokens, timezone edges, DST, Ramadan quiet-window interactions) — **landed M3.4 server-side** (the engine lives in `functions/src/streak/`, TS + fast-check, because the answerReveal trigger is its only writer per ADR-012; the app carries just a display-only zero-state-parity read model, so no Dart engine twin exists by design; Ramadan quiet-window interactions stay deferred with seasonal content, ADR-011); pairing state machine (races, expiry, re-pair attempts); question selection (register/seasonal/no-repeat determinism); entitlement mapping (one purchase → two partners; expiry → both) — **landed M4.1 server-side** (the decision core lives in `functions/src/entitlements/`, TS + fast-check, because the `revenueCatWebhook` Function is the mirror's only writer per ADR-013; the app carries just the summary read model + the `isPremium` derivation, provider-tested). **M4.3 (ADR-015) added `TRANSFER`**: the pure `gateTransfer`/`planTransfer`/`revokedLane`/`revokeLane` core is table-tested over the full case matrix (within-couple = hold; cross-couple = revoke the loser only; unknown/anon/empty destination = hold; oversized = hold at the pre-read gate; multi-target = one tombstone per losing couple) and the **convergence property now folds a TWO-COUPLE world with transfers mixed into the event multiset** — it is mutation-verified: making the tombstone copy the loser's prior lane facts, entitling a gainer, or dropping the tombstone-when-no-lane-exists rule each break order-independence and turn it red. The emulator suite proves the hazards end-to-end (the shared-Apple-ID within-couple restore leaves the doc BYTE-unchanged; the reinstall's anonymous destination never downgrades a payer; a transfer arriving BEFORE the purchase it moves cannot be resurrected by the late purchase; duplicate/stale transfers write nothing), and **one e2e wire test POSTs RC's real transfer body (no `app_user_id`) — the regression that the M4.1 envelope contract would have 400'd**; pack validator; crisis-lexicon matcher (TR/AR/EN seed lists) — **landed M5.1 server-side** (ADR-016: the pure normalizer + detector live in `functions/src/coach/`, TS + fast-check, because `coachProxy` is the only consumer; evasion resistance is normalization-based with **one property-mutation class per fold step** — NFKC forms, Cf/VS injection, tashkeel/tatweel, alef/ى/ة/hamza folds, Arabic-Indic digits, TR İ/ı + TR diacritic-strip, homoglyphs, repetition inflation, separator injection incl. token-mode entries, leet, cross-message splitting — so removing ANY fold turns CI red; seeds + canonical evasion variants are byte-pinned in the policy-headed `functions/test/fixtures/coach-crisis-seeds.json` with per-language spread guards). Tools: `flutter_test`, `mocktail`, fakes over mocks for repositories, builder-pattern test data (`aCouple().paired().withStreak(12).build()`).

**Pack validator — live since M3.1** (`content/validator/`): a pure core (`validator_core.dart`, no IO — schema fields/patterns/enums/depth bounds, cross-pack id uniqueness, `packId`↔filename↔`locale` consistency, reviewedBy warning tier per ADR-007) behind a thin IO shell (`validate.dart`, exposing an in-process `runValidator` and the ADR-010 `--sync` mode). **Runner decision:** `content/` has no pubspec, so `package:test` doesn't apply; the tests are a plain-`dart` self-checking script (`validate_test.dart`, `tool/`-script mold — 63 checks over every violation class plus shell round-trips against a temp root; any failure exits non-zero). The shell also cross-checks the validator's vocabulary against `question-pack.schema.json` itself on every run, so schema edits that outpace the core fail CI loudly.

### Functions + rules tests (`functions/test/`, M2.1) — vitest against the Emulator Suite
**Tooling decision (Session 007): vitest** over jest — TS-native via esbuild, first-class v8 coverage with `thresholds` as the §3 hard gate (proven to exit non-zero below 80%), one config. `fast-check` for property tests (code charset/length/collision). Because esbuild strips types **without checking them** and the build tsconfig covers only `src/`, `npm run typecheck` (`tsconfig.test.json`, bundler module semantics) is the step that typechecks `test/` — wired into the CI job. Three layers, all in one `firebase emulators:exec --only auth,firestore,functions --project demo-hayati 'cd functions && npm run test:ci'` run: **pure unit** (no emulator), **service/handler in-process** against the firestore emulator (admin SDK, injectable seams for error paths), and **callable end-to-end** through the functions emulator (real HTTP callable protocol + auth-emulator idTokens — note the functions emulator *skips* real token verification, so production token rejection is untestable here; handlers guard `auth.uid` themselves). The **rules suite** (`@firebase/rules-unit-testing` v5) proves every shipped invariant and adds **mutation tests**: each protecting clause is weakened in a copy of the rules (loaded under its own `demo-*` projectId — the emulator stores rules per project) and the previously-denied op must then succeed, so a commented-out rule turns the suite red instead of silently shrinking the net. **S072 addition (ADR-050, issue #223) — a lint for three workflows that have never run.** `tool/deploy_lane_lint.dart` + its self-test join the `quality` job beside the release-lane pair, and they are the **entire** protection for the guards they check: none of the three deploy lanes has ever executed, none can until operator 2(e)(iii), `actionlint` is not installed, and there is therefore no dispatch to observe and no log to read. The rules are written to catch the NEXT lane rather than re-catch these two: the lane list is a **derived** `deploy-*.yml` glob, and an empty derived set is **exit 64** — a sentinel over nothing is the greenest output in this repo. What the lint asserts, and what each assertion is defending against: `concurrency` exists **at workflow level** (a job-level block has different semantics and must not satisfy it) with an explicit `cancel-in-progress: false`; its group **interpolates** (a constant makes dev queue behind prod — a new bug, not a weaker guard), via `github.event.inputs.` (workflow-level concurrency is evaluated before any job starts, so a bad expression is a *parse* error on someone's first dispatch) and **keyed on the input that selects the target** (a group keyed on `confirm_prod` interpolates faithfully and serializes the wrong pairs); a production-capable lane carries a ref guard whose **single** expression asserts `inputs.<selector> == '<prod>'` **and** `github.ref != 'refs/heads/main'`; and that guard **precedes** the deploy, located by an explicit publish-command list rather than by guessing which step is "the deploy" — a lane whose command the list does not know is reported, never skipped. Ahead of all of it, a lane taking target-shaped inputs the vocabulary does not know is **reported rather than skipped**: without that, a future `environment: [staging, production]` lane passes the whole lint with no guard at all.

Two of those exist because the design review found them. **Two blockers, both inversions.** The first implementation matched the four *words*, which also matches `inputs.project != 'prod' && github.ref != 'refs/heads/main'` — dev blocked from a branch, prod admitted from anywhere, the guard inverted into precisely the hole it was added to close. The second survived that fix: `== 'prod' || ref != 'main'` contains both required substrings and fires on every dev dispatch from a branch, so the **conjunction** is asserted too (either operand order; `||` is not). And the review's skeptic found a third by reading for a function the header named and the file did not contain — a lane the vocabulary cannot classify was **silently skipped** while the comment claimed it would be failed. **The second:** comments are stripped before scanning, because every lane now carries a header quoting the guard — so a lint reading prose would go green on the remediation note somebody leaves behind when they *delete* it, which is the worst possible moment (`release_lane_lint.dart`'s "scan CODE, not commentary", same reasoning one file over).

**15 mutants, each reddening a named check**, with the anchor asserted present-and-unique before every edit and the file diffed byte-identical against a pre-mutation copy afterwards (lesson **109** — an earlier run in this session applied *nothing* and printed three reassuring greens).
